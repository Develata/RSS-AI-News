# 03 — AI 分析段

本章详解主链路第三段：从 `articles.state=persisted` 到 `articles.state=ready_for_publish`（或 `publish_skipped`）。

```text
persisted
  → task_gen:  INSERT article_ai_results (state='pending')，articles.state='ai_pending'
  → claim:     article_ai_results.state='pending' → 'running'，lease+attempt
  → run:       AiClient.complete() + parser.parse_response()
  → 成功:      state='succeeded'，articles.state='ai_done' 或 'ready_for_publish'
  → 过滤:      state='filtered'，articles.state='publish_skipped'
  → 永久失败:  state='permanent_failed'，articles.state 保持 'ai_pending'
```

## 1. 边界

本章覆盖：
- AiClient 抽象与 OpenAI 兼容协议
- prompt 组装（含 category override / prompt_version / output_schema_version）
- JSON 解析（含 schema drift 处理）
- `ai-run` Flow（task_gen + claim + execute）
- AI 关闭直通模式（无 LLM 发布降级）
- `replay --kind ai` 与 `backfill --target ai`

**不覆盖**：
- 正文入库 → [./02-extract.md](./02-extract.md)
- prompt_version 升级机制 → [./05-storage.md](./05-storage.md) §reindex + ADR-0004

## 2. AiClient

`AiClient` trait 在 [`crates/ai/src/client.rs`](../../crates/ai/src/client.rs) 定义。
契约：OpenAI Chat Completions API 兼容（POST `/v1/chat/completions`）。

### 2.1 兼容范围

支持的字段（最小子集）：
- `model`
- `messages[{role, content}]`
- `temperature`
- `max_tokens`
- `response_format: {type: "json_object"}`（部分 provider 支持）

**不**支持：tools / function_calling / stream / vision input。详见 [./13-non-goals.md](./13-non-goals.md)。

### 2.2 endpoint 配置

由 `.env` 提供：
- `OPENAI_BASE_URL`（如 `https://api.openai.com/v1` / `http://vllm.local:8000/v1` / `https://api.deepseek.com/v1`）
- `OPENAI_API_KEY`
- `OPENAI_MODEL`

`ai.enabled = false` 时**不**读这三个变量；`validate-config` 跳过 OpenAI 校验。

## 3. Prompt 组装

由 [`crates/ai/src/prompt.rs`](../../crates/ai/src/prompt.rs) 完成。每次调用前：

1. 加载 active prompt（按 `rule_versions` 表查 `kind='ai_prompt'` + `category_key=?`）
2. 用 article 元信息 + 正文填充模板
3. 控制总 token 数：`category.max_input_chars` 截断正文（保留 head + tail）

### 3.1 prompt 模板

每个分类一份模板，定义在 `categories/<key>.toml` `[prompt]` 段：

```toml
[prompt]
system = "你是一个 ML 研究领域的内容编辑..."
user_template = """
标题: {{title}}
摘要: {{summary}}
正文:
{{body}}

请输出 JSON: { "keep": bool, "summary": "...", "tags": [...], "score": 0-100 }
"""
max_input_chars = 4000
```

### 3.2 prompt_version 与 output_schema_version

两个独立的版本号：
- `prompt_version` — prompt 文本变更（人工 bump）
- `output_schema_version` — JSON schema 变更（如新增字段、字段重命名）

存入 `article_ai_results` 行作为冻结副本。每条 AI 结果都能定位到当时的 prompt/schema 版本。

升级机制：
- prompt 改了 → 写新 `rule_versions` 行 + 走 reindex 流程（active rule resolver）
- output schema 改了 → 同上，且 parser 需向后兼容旧 schema

详见 [./05-storage.md](./05-storage.md) §reindex。

## 4. JSON 解析

`crates/ai/src/parser.rs` 实现：

```rust
pub fn parse_response(raw: &str, schema_version: &str) -> Result<AiOutput, AiError>;
```

策略：
1. 优先尝试 `serde_json::from_str` 严格解析
2. 失败：尝试提取 fenced code block（` ```json ... ``` `）
3. 仍失败：返回 `AiError::JsonParseFailed`（不接受文本协议 fallback）

### 4.1 向后兼容

新 schema 添加字段时，parser 必须能解析旧 schema 输出（缺字段用默认值）。
单元测试覆盖每一对 (旧 schema, 新 parser) 组合。

### 4.2 关键字段

```rust
struct AiOutput {
    keep_decision: bool,           // false → state='filtered'
    summary: Option<String>,
    tags: Vec<String>,
    importance_score: Option<u8>,  // 0-100，可选
}
```

## 5. ai-run Flow

由 `AiRunFlow` 在 [`crates/runtime/src/flows/ai_run.rs`](../../crates/runtime/src/flows/ai_run.rs) 编排。

### 5.1 task_gen 阶段

为每个 `articles.state='persisted'`（且没有 active prompt 的对应 AiResult 行）创建任务：

```sql
INSERT INTO article_ai_results (article_id, category_key, prompt_version, output_schema_version, state, ...)
SELECT id, ..., 'pending', ...
FROM articles
WHERE state='persisted' AND category_key = ?  -- v0.3 category-scoped
  AND NOT EXISTS (...同 article_id 的 active version...);

-- 同事务 UPDATE
UPDATE articles SET state='ai_pending'
WHERE id IN (...) AND state='persisted';
```

v0.3 引入 `category_key` 圈定：避免对其它分类生成不必要任务。

### 5.2 claim 阶段

```sql
UPDATE article_ai_results
SET state='running', lease_owner=?, attempt_count = attempt_count + 1
WHERE state='pending' AND category_key=?  -- v0.3
LIMIT N RETURNING *;
```

### 5.3 execute 阶段

每条 task：
1. 构造 prompt
2. 调 AiClient.complete()
3. parser.parse_response()
4. 写 raw_artifact（按 retention policy）
5. UPDATE article_ai_results + articles.state（同事务）

成功 → `succeeded`；分数达门槛 → `articles.state='ready_for_publish'`，否则 `'ai_done'`。
keep_decision=false → `filtered` + `articles.state='publish_skipped'`。

## 6. AI 关闭直通模式

当 `config.ai.enabled = false`：
- `task_gen` **不**创建 AiResult 行
- `articles` 保持 `persisted`，**不**升 `ai_pending`
- 仅当 `config.publish.include_unscored = true` 时，`publish::freeze` 在选稿事务内
  把 `Persisted → ReadyForPublish` 直通升格（见 [./08-state-machines.md](./08-state-machines.md) §4.2）

`doctor` 在 `ai.enabled=false` 时跳过 `OPENAI_API_KEY` 校验。

真值表见 [./06-config.md](./06-config.md) `[ai]` × `[publish]` 矩阵。

## 7. replay --kind ai

```bash
rss-ai-news replay --kind ai --target-id <article_ai_result_id> --diff
```

从 `raw_artifacts WHERE kind='ai_raw_response' AND target_id=?` 取原始 LLM 响应，
重跑 `parse_response`，diff 输出字段（`keep_decision` / `summary` / `tags` / `importance_score`）。

read-only，不写数据库。

## 8. backfill --target ai

当 prompt 改进或新模型上线，对历史 article 重跑 AI：

```bash
rss-ai-news backfill --target ai --category ai --prompt-version v3
```

流程：
1. 注册新 `rule_versions` (kind='ai_prompt', status='pending')
2. 走 reindex 标准流程（claim + lease + batch）
3. 完成时 status → 'active'，旧 active → 'superseded'

详见 [./10-replay-and-backfill.md](./10-replay-and-backfill.md) + [../adr/0004-active-rule-resolver-partial-unique.md](../adr/0004-active-rule-resolver-partial-unique.md)。

## 9. 失败路径速查

| 失败点 | 错误变体 | retryable | 处理 |
|---|---|---|---|
| HTTP 超时 | `AiError::HttpTimeout` | true | 回 `pending` |
| 4xx | `AiError::HttpStatus { 4xx }` | false | 转 `permanent_failed` |
| 5xx | `AiError::HttpStatus { 5xx }` | true | 回 `pending` |
| 余额不足 | `AiError::QuotaExceeded` | false | 转 `permanent_failed` |
| JSON 解析失败 | `AiError::JsonParseFailed` | false | 转 `permanent_failed` |
| token 超限 | `AiError::TokenLimitExceeded` | false | 转 `permanent_failed` |
| 模型不存在 | `AiError::ModelNotFound` | false | 转 `permanent_failed` |

`permanent_failed` 不更新 `articles.state`（保持 `ai_pending`），等待 backfill 恢复。
