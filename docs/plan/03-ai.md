# 03 — AI 分析段

本章详解主链路第三段：从 `articles.state=persisted` 到 `articles.state=ready_for_publish`（或 `publish_skipped`）。

```text
persisted
  → task_gen:  INSERT article_ai_results (state='pending')，articles.state='ai_pending'
  → claim:     article_ai_results.state='pending' → 'running'，lease+attempt
  → run:       AiClient.invoke() + parser.parse_response()
  → 成功:      state='succeeded'，articles.state='ai_done' 或 'ready_for_publish'
  → 过滤:      state='filtered'，articles.state='publish_skipped'
  → 永久失败:  state='permanent_failed'，articles.state 保持 'ai_pending'
```

## 1. 边界

本章覆盖：
- AiClient 抽象与 OpenAI 兼容协议
- prompt 组装（含 category override / prompt_version / output_schema_version）
- JSON 解析（含 schema drift 处理）
- `ai-run` Flow（task_gen + claim + execute）
- AI 关闭直通模式（无 LLM 发布降级）
- `replay --kind ai` 与 `backfill --target ai`

**不覆盖**：
- 正文入库 → [./02-extract.md](./02-extract.md)
- prompt_version 语义 → §3.2（reindex 不处理 prompt）；对历史文章用新 prompt 重跑 → §8

## 2. AiClient

`AiClient` trait 在 [`crates/ai/src/client.rs`](../../crates/ai/src/client.rs) 定义。
契约：OpenAI Chat Completions API 兼容（POST `/v1/chat/completions`）。

### 2.1 兼容范围

支持的字段（最小子集）：
- `model`
- `messages[{role, content}]`
- `temperature`
- `max_tokens`

**不**支持：tools / function_calling / stream / vision input。详见 [./13-non-goals.md](./13-non-goals.md)。

### 2.2 endpoint 配置

全局凭证由 `.env` 提供：
- `OPENAI_BASE_URL`（如 `https://api.openai.com/v1` / `http://vllm.local:8000/v1` / `https://api.deepseek.com/v1`）
- `OPENAI_API_KEY`
- 模型来自 `[ai].model`，可由分类或 CLI `--model` 覆盖。

板块可经 `[category.ai_override]` 的 `base_url` + `api_key_env`（env 变量名引用）独立配置，
留空继承全局。ai-run 逐分类执行（未给 `--category` 时为全部分类），每个分类的凭证在
composition root 独立静态解析并装配一个 client；多分类时单个分类失败记入 `category_failures`，
其余分类继续。
详见 [./14-ai-fallback.md](./14-ai-fallback.md) §B（W14-B）。

`ai.enabled = false` 时不校验 AI 凭据、不构造 AI client；`validate-config` 跳过 OpenAI 校验。
`ai.enabled = true` 时全局凭证仅在存在"继承全局"的板块时必填（全部板块自带凭证 ⇒ 全局可空；
backfill 只更新待处理状态和版本，不调用 AI，无需凭据）。

### 2.3 失败回退（fallback 模型链）

主模型调用失败时，在**同一次执行内**按 `[ai].fallback_models`（板块可经
`[category.ai_override].fallback_models` 覆盖）顺序换 model 名重试。详见
[./14-ai-fallback.md](./14-ai-fallback.md)。要点：

- 一次"模型尝试" = invoke + parse + schema 校验**整段**；任一步失败且该错误"换模型可能有救"
  （quota / 限流 / 5xx / 模型不存在 / 超时 / 内容解析失败）即试下一个模型。
  `InvalidConfig`（凭证错）/ `ConnectionFailed`（连不上）换 model 名无用，不触发回退。
- 链 = `[主模型, ...fallback_models]`，去重。主模型锚定 `article_ai_results.model_id`
  （claim 出的行身份，幂等键，不可变）；fallback 后**实际成功的模型**记入非键列
  `effective_model_id`（旁路审计 / 统计）。
- 链全部失败后，按最后错误的 `is_retryable()` 回 `pending` 或转 `permanent_failed`（与原逻辑一致）。
- 横向 fallback（换模型）与纵向 `[retry].ai_max_attempts`（回队重试）正交。
- fallback 链上所有模型走**同一板块凭证**（每个分类一个 client）；板块独立 key / base_url
  见 [./14-ai-fallback.md](./14-ai-fallback.md) §B。

## 3. Prompt 组装

模板解析在 CLI composition root（`EffectiveConfig`，[`crates/config/src/effective.rs`](../../crates/config/src/effective.rs)），
渲染由 [`crates/ai/src/prompt.rs`](../../crates/ai/src/prompt.rs) `render_prompt` 完成：

1. 模板 = `[category.ai_override].prompt_template`；省略或 trim 后为空 = 内置
   `DEFAULT_PROMPT_TEMPLATE`（与 `model` / `path_template` 的继承语义一致）。
   ai-run 与 `backfill --target ai` 共用这一来源。
2. 单次扫描替换 `{title}` / `{body_text}` / `{category_key}`；其它 `{...}`（含 JSON 示例与未知
   `{name}`）原样发送，替换值中的占位符字面量不会被二次替换。
3. 正文按 `max_input_chars`（板块 `ai_override.max_input_chars` > `[ai].max_input_chars`）以
   Unicode 字符为单位**只保留开头**截断，不追加省略标记（`process.rs::truncate_chars`）。
4. 请求 = 固定 system 消息（`client.rs::SYSTEM_MESSAGE`，要求只返回 JSON）+ 渲染后的模板作为
   user 消息。输出字段约定只来自模板文本，代码不额外注入 schema。

模板缺 `{body_text}` 时正文不会发送给模型。`validate-config` 与 ai-run 对此给出非致命
warning（`code=prompt_template`），见 [./06-config.md](./06-config.md) §独立能力与保留字段。

### 3.1 prompt 模板

每个分类一份模板，写在 `categories/<key>.toml` 的 `[category.ai_override]`：

```toml
[category.ai_override]
prompt_template = """
阅读下面的文章，只输出一个 JSON 对象，字段如下：
- keep_decision：布尔值，是否值得收录
- summary：中文摘要；keep_decision 为 true 时必填
- tags：字符串数组
- importance_score：0 到 100 的整数；keep_decision 为 true 时必填
- filter_reason：不收录的原因；keep_decision 为 false 时必填

标题：{title}
正文：
{body_text}
"""
max_input_chars = 10000
```

占位符是**单花括号**。`{{title}}` 会渲染成 `{<标题>}`，`{{body}}` 等未知名称原样发送。

### 3.2 prompt_version 与 output_schema_version

两者都是 `rule_versions.id`，在建任务时写入 `article_ai_results` 行（属于幂等键
`(article_id, prompt_version, output_schema_version, model_id)`）：

- `prompt_version`：ai-run 取全局 `kind='prompt'` 的 active 行；无 active 时注册
  `version_tag='default'`。它**不按分类区分，也不由模板内容派生**——只改
  `prompt_template` 不会产生新版本号；版本行的语义由运维约定维护。
- `output_schema_version`：`kind='ai_output_schema'`，当前只有 `v1`（§4）。

`reindex` 只处理 link_hash / content_hash / categories，不处理 prompt。要对历史文章用新
prompt 产生平行结果，走 `backfill --target ai`（§8），其限制见
[./10-replay-and-backfill.md](./10-replay-and-backfill.md) §5.2。

## 4. JSON 解析

[`crates/ai/src/parser.rs`](../../crates/ai/src/parser.rs)：

```rust
pub fn parse_response(article_ai_result_id: i64, raw: &str) -> Result<ParsedResponse, AiError>;

pub enum ParsedResponse {
    Output(AiOutput),             // keep_decision = true
    Filtered(AiFilteredOutput),   // keep_decision = false
}
```

策略：
1. 整段 `serde_json::from_str`。
2. 失败：取第一个括号平衡的 `{...}` 对象（感知字符串与转义）再解析；覆盖 ```` ```json ```` 围栏
   与前后说明文字。
3. 仍失败：`AiError::InvalidJson`（不接受文本协议 fallback）。

### 4.1 v1 输出契约

| 字段 | 要求 |
|---|---|
| `keep_decision` | 必填 bool，缺失 → `MissingField` |
| `summary` | `keep_decision=true` 时必填且 trim 后非空 |
| `importance_score` | `keep_decision=true` 时必填，JSON 整数 0..=100；越界 → `InvalidFieldValue`，小数 / 字符串 → `InvalidJson` |
| `tags` | 可选字符串数组，缺省 `[]` |
| `filter_reason` | `keep_decision=false` 时必填且 trim 后非空；此时 summary / tags / score 可省略或为 null，其值不参与判定与输出，但若提供仍须类型合法（否则 `InvalidJson`） |

未知字段忽略。当前只有 v1；`parse_response` 不带 schema 版本参数。引入新 schema 时必须
同时提供按版本分派的解析与新旧组合测试，不能改写 v1 语义。

### 4.2 关键字段

```rust
// crates/domain/src/dto/ai.rs
pub struct AiOutput {
    pub article_ai_result_id: i64,
    pub summary: String,
    pub tags: Vec<String>,
    pub importance_score: Score0To100,
    pub keep_decision: bool,
    pub raw_response: String,
}

pub struct AiFilteredOutput {
    pub article_ai_result_id: i64,
    pub reason: String,             // ← filter_reason
    pub raw_response: String,
}
```

## 5. ai-run Flow

由 `AiRunFlow` 在 [`crates/runtime/src/flows/ai_run/mod.rs`](../../crates/runtime/src/flows/ai_run/mod.rs) 编排。

### 5.1 task_gen 阶段

为每个 `articles.state='persisted'`（且没有 active prompt 的对应 AiResult 行）创建任务：

```sql
INSERT INTO article_ai_results (article_id, category_key, prompt_version, output_schema_version, state, ...)
SELECT id, ..., 'pending', ...
FROM articles
WHERE state='persisted' AND category_key = ?  -- v0.3 category-scoped
  AND NOT EXISTS (...同 article_id 的 active version...);

-- 同事务 UPDATE
UPDATE articles SET state='ai_pending'
WHERE id IN (...) AND state='persisted';
```

v0.3 引入 `category_key` 圈定：避免对其它分类生成不必要任务。

### 5.2 claim 阶段

```sql
UPDATE article_ai_results
SET state='running', lease_owner=?, attempt_count = attempt_count + 1
WHERE state='pending' AND category_key=?  -- v0.3
LIMIT N RETURNING *;
```

### 5.3 execute 阶段

每条 task（`process.rs::process_one`）：
1. 读文章，按 §3 截断正文，构造 `AiTask`
2. 对模型链 `[claimed.model_id, ...fallback]` 逐个尝试：`AiClient.invoke()` → 写
   raw_artifact（**不受** `retention_policy` 控制，每次尝试都写，见 plan/10 §3；attempt 0 的 key 为
   ai_result id，fallback 为 `{id}#a{n}`）
   → `parse_response()`；可回退错误换下一个模型（§2.3）
3. UPDATE article_ai_results + articles.state（同事务）

成功 → `succeeded`；分数达门槛 → `articles.state='ready_for_publish'`，否则 `'ai_done'`。
keep_decision=false → `filtered` + `articles.state='publish_skipped'`。

## 6. AI 关闭直通模式

当 `config.ai.enabled = false`：
- `task_gen` **不**创建 AiResult 行
- `articles` 保持 `persisted`，**不**升 `ai_pending`
- 仅当 `config.publish.include_unscored = true` 时，`publish::freeze` 在选稿事务内
  把 `Persisted → ReadyForPublish` 直通升格（见 [./08-state-machines.md](./08-state-machines.md) §4.2）

`doctor` 在 `ai.enabled=false` 时跳过 `OPENAI_API_KEY` 校验。

真值表见 [./06-config.md](./06-config.md) `[ai]` × `[publish]` 矩阵。

## 7. replay --kind ai

```bash
rss-ai-news replay --kind ai --id <raw_artifacts.id>
rss-ai-news replay --kind ai --key <article_ai_result_id>      # fallback 尝试：<id>#a<n>
```

取 `kind='ai_raw_response'` 的 inline 原始响应，重跑 `parse_response`，输出
`keep_decision` / `summary` / `tags` / `importance_score`（或 filter reason）。
`--diff` 对 ai 目前返回 `{"supported": false}`，不与入库结果比对。

read-only，不写数据库。

## 8. backfill --target ai

对历史 article 插入平行的 pending AI 任务，由后续 ai-run 消费：

```bash
rss-ai-news --category ai backfill --target ai --prompt-version-tag v3 --date-from 2026-05-01
```

流程（`flows/backfill.rs`）：
1. `get_or_create` 一行 `kind='prompt'` 的 `rule_versions`（payload sha 取自所选分类的生效模板；
   已有 active 行时新行为 `pending`，不会被激活）
2. 分页扫描窗内**所有分类**的非 retired article，插入 `pending` 的 `article_ai_results`
   （新 prompt_version，`model_id` = `--model` 或全局 `[ai].model`）；同一元组冲突跳过
3. 不改 article 状态，不走 reindex / lease

ai-run 处理这些行时使用各自分类**当前**的模板与凭证，链首模型为行内 `model_id`。
已知限制与适用范围见 [./10-replay-and-backfill.md](./10-replay-and-backfill.md) §5.2。

## 9. 失败路径速查

"fallback?" = 该错误是否触发**换模型重试**（见 §2.3 / [./14-ai-fallback.md](./14-ai-fallback.md)）。
"链尽后" = fallback 链全部失败后的最终处理（按 `is_retryable()`）。

| 失败点 | 错误变体 | fallback? | 链尽后 |
|---|---|---|---|
| HTTP 超时 | `AiError::HttpTimeout` | 是 | 回 `pending`（retryable）|
| 连接失败 | `AiError::ConnectionFailed` | 否 | 回 `pending`（retryable）|
| 限流 429 | `AiError::RateLimited` | 是 | 回 `pending`（retryable）|
| 5xx | `AiError::HttpStatus { 5xx }` | 是 | 回 `pending`（retryable）|
| 其它 4xx | `AiError::HttpStatus { 4xx }` | 是 | 转 `permanent_failed` |
| 模型不存在 | `AiError::ModelUnavailable` | 是 | 转 `permanent_failed` |
| 余额不足 | `AiError::QuotaExceeded` | 是 | 转 `permanent_failed` |
| JSON 解析失败 | `AiError::InvalidJson` | 是 | 转 `permanent_failed` |
| schema 缺字段 / 非法 | `AiError::MissingField` / `InvalidFieldValue` | 是 | 转 `permanent_failed` |
| 空响应 | `AiError::EmptyResponse` | 是 | 转 `permanent_failed` |
| 配置无效 | `AiError::InvalidConfig` | 否 | 转 `permanent_failed` |

`permanent_failed` 不更新 `articles.state`（保持 `ai_pending`），等待 backfill 恢复。
fallback 链中每次失败尝试的原始响应各自留一份 raw_artifact（key 含 attempt/model），不互相覆盖。

## 执行边界（2026-09-10）

AI 唯一生产请求实现为 reqwest OpenAI-compatible JSON。一次 process 共享 Arc<AiRunOptions>，
模板为 Arc<str>；每条任务正文按 Unicode 字符边界原地截断，模型回退复用已准备的数据。
成功响应最多4 MiB，超限 ResponseTooLarge 不作跨 run 重试，但可尝试下一个 fallback model。
错误消息先解析JSON转义、遮蔽当前API key并按完整内容分类，然后截为最多 8 KiB。
`error.type` / `error.code` 仅在字符串类型时参与分类，不因其它字段类型异常跳过 message 脱敏。
合法 JSON 缺少字符串 `error.message` 时仅输出状态说明，不回显未知结构中的键或嵌套值。
JSON 解析失败（含深度超限、截断及纯文本）时，保留原 HTTP/正文分类和 Retry-After，诊断替换为固定的正文省略说明，避免未解码转义泄漏凭据。
`display_user()` 的最终诊断最多 16 KiB，覆盖自定义 AiClient 返回的错误；截断包含 UTF-8 安全前缀与原字节数标记。
汇总只保留计数和最多32条失败样例，当前批次完成后不累计成功 DTO。
滚动 JoinSet 的存活任务数不超过 `http.concurrent_fetches.max(1)`；claim 数据仍占 O(batch size)，
保留原有 lease budget 校验及批内 retryable 失败后停止、跨 run 重试语义。
