## 核心交付

正确性：

- 单分类 `publish` 各阶段（freeze / render / store-local / remote）只领取 init 得到的记录，不再领取或推进其他分类残留的 Pending 记录；PostgreSQL 按 ID claim 使用 `FOR UPDATE SKIP LOCKED`，不再被持锁事务无限阻塞。
- 阶段失败经 summary 反映到退出码：publish 阶段 `failed`、ingest / ai-run 存储失败（claim、候选查询、pending 插入、entry 插入、source 状态写回）不再报 success / exit 0；`run` 汇总子阶段 summary 的非零退出码。
- JSON 模式 stdout 恰好一个文档：`doctor` 失败不再输出两个 JSON，`rebuild-report` 不再在 JSON 前打印 Markdown；失败 envelope 的 `command` 为实际调用的命令。
- 多分类：`ai-run` 未给 `--category` 时逐分类执行（各用自己的凭证 / 模型 / prompt），`run` 同样；此前多于一个分类时 AI 阶段每次失败。`run` 只加载一次配置、打开一次连接池；单个分类缺凭证只记为 ai-run 阶段失败，ingest 与 publish 照常执行。
- 当天无候选（`SnapshotEmpty`）时发布记录回到 `pending` 并退还该次 attempt，同日后续运行有新文章时照常发布（此前记录直接 `failed`，当日后续 publish 冲突）。
- `publish-all` 单个分类 init 失败或终态冲突只记入该分类，不再中止其他分类与远端 batch；`reindex --abort` 不存在的 job 退出 1。
- 报告 frontmatter 按 PyYAML（YAML 1.1）与 YAML 1.2 core 的并集判定引号：会被误读或无法加载的值加引号并转义控制 / 非打印字符，合法 plain 值保持原字节；code span 中反引号不再提前结束 span。

易用性：

- `--help` 为每个子命令、参数和枚举值提供说明，顶层列出流程、首次使用顺序与退出码表。
- 全局 `-n/--dry-run`：`reindex` 实装；只读命令为无操作；其余命令（含 doctor、migrate check）在任何副作用（日志文件、metrics、存储）之前以参数错误拒绝（exit 2）。此前多数命令静默忽略该参数并真实写入。
- 移除从未实现的 `ingest --source`。

验收与 CI：

- `cargo acceptance`：子进程输出有界（每流末尾 4 MiB）、step 超时并 best-effort 杀进程树、Ctrl-C 可终止子构建、失败证据统一脱敏；产品 smoke 在一次性工作区内运行并清除产品读取的环境变量；新增真实 binary 的 JSON 单文档 / 退出码契约 smoke。小磁盘构建参数改为显式 `--low-resource`（本机 static+sqlite+release 由 821s 降至约 55–114s，依赖已缓存）。
- CI 的 lint / test / migration-smoke / test-pg 调用对应 acceptance lanes（新增 release lane 与 tooling-boundary / acceptance-docs 检查进入 CI）；`release.yml` 新增 `verify` job，tag 版本与 workspace / lockfile / README / binary 一致且 local profile 通过后才推镜像。

## 升级与行为变更

无数据库迁移；配置文件格式不变。调度方 / 脚本需注意：

| 变更 | 影响 |
|---|---|
| 阶段失败退出非零 | 此前被隐藏的失败会触发告警 |
| 多分类 `run` / `ai-run` 实际调用 AI | 开始产生真实 API 调用与费用 |
| `-n` 与写入类命令、doctor、migrate check 组合 → exit 2 | 依赖 `-n doctor` 等的脚本需调整 |
| 移除 `ingest --source` | 传入该参数会 clap 报错（exit 2） |
| `run` 启动不再做全局凭证 gate | 缺凭证从整体 exit 78 变为 ai-run 阶段失败（仍 exit 78），其他阶段照常执行 |
| `rebuild-report` 无 `--output` | pretty 仅输出 Markdown 原始字节（不补末尾换行）；JSON 放入 `summary.markdown` |
| 新 JSON 字段 | `verdict`、`categories`、`category_failures`、`markdown`、`sources_storage_failed` 等（新增，不删除既有字段） |
| frontmatter 引号修正 | 此前会被误读的值（如 `[AI]`、`true`、数字）重建后字节变化；已正确的值不变 |
| acceptance 小磁盘 | 需显式 `--low-resource` |

回退：无 schema 变化，可直接换回 v0.8.1 二进制 / 镜像；v0.9.0 期间保留为 `pending` 的空日期记录在 v0.8.1 下按旧语义处理。

- 历史空日期的 `pending` 记录会累积，doctor 暂不单列统计。

- 不对真实 AI provider 或 GitHub 内容发布做生产写入验收；使用 mock / integration tests。
