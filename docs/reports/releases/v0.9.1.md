# Release v0.9.1

- 状态：已发布；exact-SHA CI、release workflow 与 GHCR 读回核验通过
- 目标 tag：`v0.9.1`
- 日期：2026-10-16
- 范围：`v0.9.0..v0.9.1`

## 核心交付

安全（依赖更新，无代码改动）：

- rustls 0.23.38 → 0.23.46：修复 RUSTSEC-2026-0285（TLS 1.3 握手消息跨加密层级被接受）、
  RUSTSEC-2026-0346 / -0348 / -0349。rustls 经 reqwest / hyper-rustls / octocrab 处于实际依赖图，
  覆盖 feed、正文抓取、AI 与 GitHub 的全部 HTTPS 出站。
- quinn-proto 0.11.16 → 0.11.19（RUSTSEC-2026-0338 至 -0342）：仅 lockfile 条目，不在本目标的
  normal 依赖图中（`cargo tree -e normal -i quinn-proto` 无输出）。
- Dependabot cargo-compatible 组 12 项兼容更新（tokio 1.53.1、serde 1.0.229、serde_json 1.0.151、
  time 0.3.55、clap 4.6.7、octocrab 0.54.2 等）。

正确性：

- 分类未写 `[category.ai_override].prompt_template`（或写空串）时，模型此前只收到
  `Summarize the following article.`，标题与正文都未发送；现改用内置默认模板
  （`{category_key}` / `{title}` / `{body_text}` 与 v1 输出字段说明）。ai-run 与 `backfill --target ai`
  的模板、ai-run 的 `max_input_chars` 统一取自 `EffectiveConfig`。
- AI 开启时，生效模板缺 `{body_text}` / `{title}` 或含未支持的 ASCII `{标识符}`：`validate-config`
  输出非致命 `prompt_template` warning（带 `category` 字段），ai-run 每次运行记 warn 日志；不回显模板。
- `dedup.link_normalizer_version` 偏离 `"1"` 时输出 `inert_config` warning（只有一个内置实现）。
- 随附示例 `configs/categories/ai.toml.example` 的 prompt 改为含占位符与字段说明。

文档：

- plan/03、05、06、10、13、14、acceptance case 与 README 按代码校正（prompt 来源与占位符、v1 输出
  契约、parser 策略、replay 参数、backfill 范围与限制、rebuild-report 参数、ai-run 逐分类执行）。
- 登记 open 漂移：D-007（`retention_policy` 与实现不一致）、D-008（`backfill --date-to` 的 help 写
  "含"，SQL 不含当天）。只改文档描述现状，实现方向待定。

CI 与发布：

- CI 由 5 个 job 合并为 `test`（static + workspace）、`test-pg`（postgres + sqlite + release，共用一次
  release build）与 `docker-build`；lane 集合不变，runner 不 fail-fast。
- Docker builder 用 cargo-chef（版本与各架构 SHA-256 固定）把依赖编译放进可缓存的普通 layer。
- `release.yml` 的 `verify` 拆为 `verify-test` / `verify-release`，复用 `main` 上 CI 保存的缓存；两者
  都通过才推镜像。v0.9.1 是该结构的首次 tag 运行。
- maintenance 的 cargo-audit 改为校验 SHA-256 的预编译二进制；Dependabot 关闭对已开 PR 的自动 rebase。

## 升级与行为变更

无数据库迁移；配置文件格式不变，旧配置照常加载。

| 变更 | 影响 |
|---|---|
| 未写 / 空串 `prompt_template` 的分类改用内置默认模板 | 这些分类的 AI 请求开始包含标题与正文，结果与费用随之变化；已在模板中写占位符的分类不受影响 |
| 上述分类的 `backfill --target ai` prompt sha 变化 | 版本行指纹不同（backfill 不改已有结果） |
| `validate-config` JSON `summary.warnings[]` | 可能新增 `code=prompt_template` 项与可选 `category` 字段（增量，不删既有字段）；exit code 不变 |
| ai-run 日志 | 模板缺占位符时每次运行出现 warn 行 |

回退：无 schema 变化，可直接换回 v0.9.0 二进制 / 镜像（会重新引入上述 rustls advisory）。

## 已知边界

- D-007：`retention_policy=on_failure`（默认）下 feed / HTML 原文不留档；AI 原始响应不受策略控制，
  始终写入。

- `backfill --target ai` 不按分类过滤、`model_id` 取全局模型（生产未使用，见 plan/10 §5.2）。

  会误报通过；Ubuntu noble 的 ripgrep 链接 PCRE2，推断当前 CI 扫描正常（未在 CI 上直接验证）。
- Docker `cache-to` 在 PR / tag 上仍写缓存，maintenance 的 rust-cache 未限制 `save-if`；未见污染 main
  产物的证据。
- rustdoc `-D warnings` 的 30 处 intra-doc link 告警未修。
- 不对真实 AI provider 或 GitHub 内容发布做生产写入验收；使用 mock / integration tests。
