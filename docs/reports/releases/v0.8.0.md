## 核心交付

1. **按 flow 收窄依赖**：以 `RunMeta` 和各 flow 的 `*Deps` 替换共享 `RunContext`；domain 移除 SQLx 耦合，具体 health checks 归 runtime doctor。
2. **资源边界**：ingest、extract、AI 使用滚动任务集合；失败摘要有界保留；减少正文、prompt、feed/HTML 和报告路径的复制与临时分配。
3. **命令与状态正确性**：真正接入 Readability；只读维护命令不自动迁移；doctor 使用只读连接；迁移状态检查包含版本、成功标记和 checksum；reindex dry-run 模拟冲突链；远端发布准备与请求共用 deadline。
4. **诊断与响应安全**：限制 AI、GitHub 和 health 响应大小；JSON 解码后移除回显凭据；provider 诊断最多 8 KiB、事件消息最多 16 KiB，序列化 context 最多 4 KiB。
5. **依赖与容器维护**：移除 async-openai 及闲置依赖链，保留已验证的安全更新；Docker 改用真实源码和 BuildKit cache mounts；supercronic 0.2.49 按架构验证 SHA-256。
6. **持续验证**：维护工作流、依赖策略、性能夹具和 SQLite 查询计划检查。
7. **发布前补充修复**：修复 provider 错误 JSON 字段类型异常、深度超限或截断时的转义凭据泄漏；AI 容忍非字符串分类字段，未知结构及无法解析的正文仅保留固定说明与原分类信号。AI/GitHub 回归均先复现失败，62 项相关测试通过；独立安全复核通过。

## 兼容、升级与回退

- 本轮没有数据库 schema、migration 文件或默认配置变更；从 v0.7.1 升级无需新增迁移。部署前仍应使用 `migrate check` 核对既有 schema。
- `doctor`、`replay`、`rebuild-report`、`recent-entries` 和 `reindex --dry-run` 不创建缺失数据库或自动迁移。新部署请先显式执行 `migrate run`。
- `reindex` 是全局规则操作，拒绝 `--category`，返回 exit 2。hash dry-run 超过 100,000 行时明确失败，不输出不完整统计；大库使用正常分批 reindex。
- `ingest/ai-run --batch-size` 与 `run --ingest-batch-size/--ai-batch-size` 接受 `1..=10000`；越界在参数解析时返回 exit 2。AI lease 预算仍可能要求更小的批次。
- Rust 源码调用方需适配 `*Deps`、`Arc<str>` prompt、`failure_samples` 摘要及 health 构造器的 `SecretString` 参数。版本提升为 0.8.0，以明确标示这些接口变化。
- Readability 接通后，新抓取的正文及其 hash 可能不同；既有文章和已冻结报告不会因升级自动重写。本轮不要求主动 reindex。
- 回退时停止调度中的新任务，切回固定的 `0.7.1` / `0.7.1-scheduler` 镜像；无需 down migration。回退会重新暴露旧版已知的资源与诊断问题。

## 已知边界

- 同步渲染不能被抢占；deadline 检查限制后续行为，不保证函数总耗时严格位于 lease 内。
- SQLite 沿用既有时间戳文本比较：无小数的 feed 时间在与带小数的查询上界同秒时，可能暂不入选，至下一秒恢复；该行为已在 v0.7.1 存在。本轮端到端管线使用发布于一分钟前的夹具，未改写该存储契约。
- claim 数据与正文仍占用与批次相关的内存；不宣称整体常量内存或普遍提速。
- 依赖审计沿用仓库的 inactive RSA 例外；`fxhash` 停止维护以及 `chacha20`、`spin` 被 yanked 的警告单独记录，未作额外升级。
- 不把真实 AI provider 或 GitHub 内容发布写入作为发布门槛；相关路径由 mock/integration tests 验证。
