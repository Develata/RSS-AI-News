# Release v0.10.3

- 状态：已发布；exact-SHA CI、release workflow 与 GHCR 读回核验通过
- 目标 tag：`v0.10.3`
- 日期：2026-11-18
- 范围：`v0.10.2..v0.10.3`

## 核心交付

安全：

- **修复 RUSTSEC-2026-0459（libsqlite3-sys 捆绑的 SQLite）。** SQLx 0.8.6 → 0.9.1，libsqlite3-sys 0.30.1 → 0.40.0
  （advisory 的修复版本为 ≥ 0.39.0）。捆绑的 SQLite 从 3.46.0 升到 3.54.1，依据是两版 crate 源码中 `sqlite3.h` 的
  `SQLITE_VERSION`，二进制里的版本字符串与之一致。
  - SQLx 0.9.1 要求 libsqlite3-sys `>=0.30.1, <0.41.0`，这个范围仍包含有漏洞的版本，所以只升 SQLx 时锁文件会留在 0.30.1。
    锁文件用 `cargo update -p libsqlite3-sys --precise 0.40.0` 显式抬升，现在锁文件里只有这一个版本。
  - manifest 写 `0.9.1` 而不是 `0.9`，因为 0.9.0 不允许 ≥ 0.38。
- **`.cargo/audit.toml` 不再接受任何 advisory。**
  - RUSTSEC-2026-0459 的例外随修复删除。
  - RUSTSEC-2023-0071（rsa）的例外一并删除。v0.10.2 锁文件中 rsa 唯一的依赖方是 sqlx-mysql 0.8.6；sqlx-mysql 0.9 把它移到
    `mysql-rsa` feature 之后，rsa 已不在锁文件中。
  - 依赖策略脚本和 octocrab 的 `jwt-aws-lc-rs` 选择保留，它们仍禁止任何版本的 rsa 进入 active graph。
    RustSec 已把这条 advisory 的修复版本标为 `>= 0.10.0`；受影响版本的 rsa 哪怕只以 inactive 形式回到锁文件，
    `cargo audit` 也会失败。

正确性：

- **PostgreSQL 不再支持 `hostaddr`。** 环境变量 `PGHOSTADDR`（任何值，包括空串）和 `DATABASE_URL` 的 `hostaddr` 参数，
  只要出现其中一个，数据库命令和 `validate-config` 都在配置阶段以 exit 78 退出。PG 建池入口在 storage 层做同样的
  检查。原因见下一节。

代码适配（行为不变）：

- SQLx 0.9 的 `query*()` 只接受 `SqlSafeStr`（例如 `&'static str`），运行期 `format!` 出来的 `String` 不再被接受。
  - reindex_jobs 的 3 条 SELECT 原本在运行期用 `format!` 拼接，现改为编译期 `concat!` 常量。新旧 SQL 只差空白
    （原先的换行和缩进），列、谓词、占位符和排序都相同。
  - `doctor` 深度扫描和 3 个测试文件里的夹具用 `AssertSqlSafe` 标注，只拼接静态 SQL 或测试生成的 schema 名，运行期值
    仍走 `bind`。replay 的测试夹具改为绑定参数，不再需要 `AssertSqlSafe`。

依赖图：锁文件从 496 个包减到 485 个。新增和删除的包版本都能从 SQLx 到达：
- rsa 及其 pkcs1、pkcs8、spki、der、num-bigint-dig 等依赖移除。
- whoami 2、flume 0.12、hashlink 0.11 等随 SQLx 更新。

其余变化：
- 共享包按 SQLx 的要求升级，例如 libc 0.2.185 → 0.2.191。
- feature 统一后依赖边收缩，例如 lazy_static 不再依赖 spin，num-traits 不再依赖 libm。
- winapi-util 依赖的 windows-sys 从 0.48.0 换成锁文件里已有的 0.61.2，只影响 Windows。
- storage crate 新增对 `url`（锁文件中已有）的直接依赖，用于 `hostaddr` 检查。

## 升级与行为变更

无新数据库迁移，配置文件格式不变。

| 变更 | 影响 |
|---|---|
| SQLx 0.9.1 接管 0.8.6 写下的 `_sqlx_migrations` | 无需操作；checksum 不变 |
| 捆绑 SQLite 3.46.0 → 3.54.1 | 只涉及 SQLite 驱动；时间戳的存储类型和文本格式不变 |
| 环境里有 `PGHOSTADDR`，或 PG 的 `DATABASE_URL` 带 `hostaddr` 参数 | 原先：按 SQLx 0.8 的规则连接；现在：配置错误，exit 78 |

**为什么不再支持 `hostaddr`。** SQLx 0.8 把 `hostaddr` 当作 host：
- `PGHOSTADDR` 会被 `DATABASE_URL` 里的 host 覆盖；
- 空的 `PGHOSTADDR` 也会顶替 `PGHOST`；
- URL 参数 `hostaddr` 走 TCP。

SQLx 0.9 把它存为单独的字段，TCP 连接时优先用它，但 socket 路由（`PGHOST` 或 URL host 指向目录）又优先于它。
以下组合在两版之间会连到不同的服务器。前两条是实测，第三条依据源码：
- URL host 为 `db.invalid`、`PGHOSTADDR=127.0.0.1`：0.8.6 连不上，0.9.1 连到了 127.0.0.1 上的库。
- 空 `PGHOSTADDR`、`PGHOST` 指向 socket、URL 不写 host：0.8.6 以空 host 走 TCP，0.9.1 走 socket。
- URL 带 `hostaddr`、`PGHOST` 指向 socket：0.8.6 走 TCP 到该 IP，0.9.1 走 socket。

SQLx 0.9 没有清除该字段的接口，无法原样恢复旧行为，所以一律拒绝。

不涉及 `hostaddr` 时，在本项目的 Tokio 路径上，两版选择相同的 socket 路径或 TCP 主机与端口。依据：
- 两版源码对照：`PGHOST` 与默认 host 的回退相同，URL 参数集合与处理顺序相同，socket 选择相同；
- 第三轮审查另用两版 CLI 对照了 15 组输入，结果一致。

需要固定 IP 时：
1. 取消 `PGHOSTADDR`；
2. 删掉 `DATABASE_URL` 里所有 `hostaddr`、`host` 和 `port` 查询参数，因为 `host` 参数会覆盖 URL 的 host；
3. 把 IP 和端口写在 URL 的 host 部分。

仓库内的部署配置都不使用 `PG*` 变量。报错文本是固定常量，不含 URL 和变量值，并给出上述步骤。

回退：可直接换回 v0.10.2，但 RUSTSEC-2026-0459 会重新暴露。已验证 v0.10.2 的 SQLx 0.8.6 二进制能接管由 0.9.1 迁移并写入的
SQLite 和 PostgreSQL 16 库：
- `migrate check` 通过，`_sqlx_migrations` 不变；
- `doctor`、`recent-entries` 的输出与 0.9.1 一致（`generated_at` 除外）；
- `publish --local-only` 的结果与 0.9.1 相同。

## 已知边界

- 不再支持 `hostaddr`。需要它的部署（例如保留 TLS 主机名、同时固定 IP）要等以后专门设计。
- 回退和升级的双版本实测用的是 debug 构建；release 构建只经过 acceptance 的 release lane。
- macOS 上的验证覆盖 arm64；x86_64 只经过 CI 和 release workflow。
- 生产环境的升级未在发布前验证。
