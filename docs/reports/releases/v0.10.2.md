## 核心交付

正确性：

- **Jev 经 OpenRouter 时不再被判为永久失败。** OpenRouter 的 System One API（`POST https://openrouter.ai/api/v1/systemone`，
  可经 new-api 的 TypeSafe 插件渠道接入）在响应 `model` 里报告自己的模型 id，如 `typesafe/jev-1.14-20261014`。原校验对别名只接受
  `jev-` 前缀、对版本号要求完全相等，于是每个这样的响应都是 `InvalidResponse`，`decision-run` 把它归为单篇永久失败并转 `failed`。
  现在：
  - 别名（`jev-latest` / `jev-preview`）另接受 `typesafe/jev-…`；
  - 版本号另接受 `typesafe/<请求值>`，可带 `-YYYYMMDD`（`jev-1.13` 匹配 `typesafe/jev-1.13-20260917`）；
    `jev-1.13.0` 不匹配 `typesafe/jev-1.13-…`，不猜测两家版本号的对应；
  - `reported_model` 按原样保存，可据此区分上游（TypeSafe 直连为 `jev-…`，OpenRouter 为 `typesafe/jev-…`）与实际版本；
  - 凭据反射检查对新接受的形式照常生效。

  规则见 [ADR 0010 §4](../../adr/0010-typed-decision-capability.md) 与 [plan/18 §3](../../plan/18-typed-decision.md) 的 2026-11-17 修订。

## 升级与行为变更

无数据库迁移；配置文件格式不变。

| 变更 | 影响 |
|---|---|
| Jev 响应 `model` 为 `typesafe/jev-…` | 原先：`InvalidResponse`，该行转 `failed`；现在：按上述规则接受 |
| 其它 `model` 取值 | 不变 |

**只修复此后的请求。** 升级前经 OpenRouter 判为失败的行不会自动重试：生成任务时跳过已有行，领取只取 `pending`。确认存在后，可只重置
这一种失败（先查后改；`attempt_count` 归零给回完整重试预算）：

```sql
SELECT count(*) FROM decision_results
WHERE provider = 'jev' AND state = 'failed'
  AND last_error_kind = 'decision_invalid_response'
  AND last_error = 'invalid decision response: reported model does not match the requested model';

UPDATE decision_results
SET state = 'pending', attempt_count = 0, completed_at = NULL,
    last_error_kind = NULL, last_error = NULL, updated_at = NOW()
WHERE provider = 'jev' AND state = 'failed'
  AND last_error_kind = 'decision_invalid_response'
  AND last_error = 'invalid decision response: reported model does not match the requested model';
```

回退：无 schema 变化，可直接换回 v0.10.1（OpenRouter 响应会重新被判为永久失败）。
