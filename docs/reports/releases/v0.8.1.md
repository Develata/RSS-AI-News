## 核心交付

- Artifact TTL：ingest / AI process 启动各清理最多 500 条过期 inline artifact；保留业务正文、AI 结果和冻结报告，清空对应 artifact 引用。关闭新增留档不取消既有期限。
- SQLite 原子删除并保守处理同秒时间精度；PostgreSQL 使用 SKIP LOCKED，事务局部 1 秒 lock timeout / 5 秒 statement timeout，失败回滚并允许主流程继续。
- `validate-config` 对 15 个保留字段或枚举值的非默认设置输出非致命 warning，不回显配置值；默认示例保持静默。README、配置契约和 artifact 文档统一为当前真实行为。
- 固定 v0.7.1 配置字节与代表性旧库数据，验证升级、重复迁移、业务与快照保留及索引迁移回退。

## 升级与回退

本版本新增双方言 `0005_artifact_reference_indexes`，为文章及 AI 结果的 artifact 外键增加索引。
旧 0001–0004 迁移及默认配置字节不变。旧配置可继续使用。

已有部署停止调度，使用新版二进制和原配置执行：

```bash
rss-ai-news --config-dir configs migrate run
rss-ai-news --config-dir configs migrate check
rss-ai-news --config-dir configs validate-config
```

两个索引的首次创建需要扫描业务表，可能持锁，应安排维护窗口后恢复调度。
回退 v0.8.0 / v0.7.1 前，使用 SQLx migration undo 撤销 0005 及其 ledger 记录，再切换旧二进制。
直接换回旧镜像会因 exact migration-state 检查而被拒绝；不可仅删除迁移记录而保留 schema 漂移。
TTL 已删除的过期原文不可通过降级恢复，仍需 replay 的数据应在到期前保留。

CLI 既有 aggregate 字段保留，有告警时新增 `summary.warnings`，有效配置仍返回 exit 0。
直接用 Rust struct literal 构造 `ValidateConfigSummary` 的调用方需补充 `warnings`；
已有自定义 `RawArtifactRepository` 实现可继续编译，默认清理返回明确 unsupported 错误。

## 已知边界

- 每次最多删除 500 条，不保证耗时严格 O(batch)：索引访问、payload 页回收与实际引用更新数仍有成本。
- 没有 ingest/AI 调用时不清理；积压需多次运行；SQLite 文件不会自动缩小。
- `expires_at=NULL` 和 file-backed 行保留；当前 artifact 后端仅数据库 inline，debug_only 未实现。
- RPM/TPM limiter、HTTP 内层 retry、关闭 dedup、文件后端仍未实现；警告不代表启用这些功能。
- 依赖图未升级：沿用 inactive RSA 策略，fxhash 停止维护与 chacha20/spin yanked 警告继续明确记录。
- 不对真实 AI provider 或 GitHub 内容发布做生产写入验收；使用 mock/integration tests。
