## 核心交付

正确性：

- `decision-run` 不再被单篇 403 卡死：decision provider 的 HTTP 403 原先与 401 一样归为 `Unauthorized`
  （全局、退还次数），被 WAF 拦下的文章因此永远到不了 `max_attempts`，每次运行都最先被领取并让整次运行停下。
  现在只有 401 是 `Unauthorized`；403 归为 `HttpStatus`（疑似配置：计次、本次停止、exit 1），该文章计满次数后
  转 `failed`，后续运行不再被它挡住。代价：持续的全局 403 也会消耗各行的次数预算。修订记录见
  [ADR 0010 §5](../../adr/0010-typed-decision-capability.md)、[ADR 0011 §10](../../adr/0011-decision-run-shadow-runner.md)
  与 [plan/18 §5](../../plan/18-typed-decision.md)。
- `replay --kind html --diff` 原先把 artifact key（feed entry id）当作 `articles.canonical_link` 查找，永远输出
  `found: false`；现经 `feed_entries.article_id` 找到文章（含 content_hash 去重命中的条目），并在输出中给出
  `article_id`。`replay --id` 现在校验 artifact kind，kind 不符按未找到处理，不再按错误的 kind 解析。
  去重时 artifact 的语义（先写者为准，不补挂）写入 [plan/02 §4](../../plan/02-extract.md)。

内部与工具：

- 删除 `ClassifiedError::display_debug`（9 个实现，无调用方）。
- 新增只读的 PostgreSQL 导出脚本 `tools/decision-eval/phase-c-export.psql`（Phase C 人工标注用，单个 REPEATABLE READ READ ONLY 事务）。
- workspace 测试与 acceptance 超时清理在 macOS 上通过（进程树发现改用 POSIX `ps`、BSD socket 非阻塞继承、
  未监听端口的连接测试）。

  仅本地向量：需打开构造过的 db + `-wal` 文件对）。

## 升级与行为变更

无数据库迁移；配置文件格式不变。

| 变更 | 影响 |
|---|---|
| decision provider 返回 403 | 原先：退还次数、exit 78；现在：计次、本次停止、exit 1。持续的全局 403 会让行逐步到达 `max_attempts` 转 `failed` |
| `replay --kind html --diff` | 能找到文章；JSON 输出增加 `article_id` |
| `replay --id` 指向其它 kind 的 artifact | 原先按请求的 kind 解析；现在报 artifact 未找到 |

回退：无 schema 变化，可直接换回 v0.10.0 二进制 / 镜像（会重新引入 403 卡死）。
